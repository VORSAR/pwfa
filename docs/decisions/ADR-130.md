# ADR-130 — Owner decisions as plain-language multiple-choice questions

Accepted on 2026-11-28. The owner directed that decisions put to the owner take the form of multiple-choice questions with pros and cons, a ranking and a recommendation, in non-technical language as far as possible. This is a standing rule across PWFA. [Project workflow](../../CONTRIBUTING.md#asking-the-owner-for-a-decision) · [Lean checks before options](ADR-117.md)

## Decision

When a choice belongs to the owner, ask it as a multiple-choice question. Word the question so it can be answered without reading anything else. Give each option a short description in plain language with its advantages and disadvantages. Rank the options on three criteria: alignment with the original vision, feasibility, and accuracy. List them best first, mark one as recommended, and give the reason. Keep formulas, technical terms and evidence in linked documents. Where a technical term cannot be avoided, explain it in a few words.

The rule changes how options are presented. The earlier duties stay in force: check formalizable assumptions in Lean before presenting options, record the owner's selection in an ADR, and never decide on the owner's behalf. [Vision statement](../vision/vision-statement.md) · [Workflow](../../CONTRIBUTING.md#workflow-owner-directive-2026-11-22)

The owner did not define accuracy further. Until the owner says otherwise, read it as the expected effect on exact recall or, for a process choice, on the correctness of the project record.

## First application

On the same day three open choices were put to the owner in this form: the next recall experiment, the comparator for the mission criterion, and how internal review notes identify the reviewer. [Roadmap](../roadmap.md) · [Mission criterion](ADR-100.md) · [Review policy](ADR-109.md)
