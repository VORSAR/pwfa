# ADR-112 — Total site counts for the first torus grids

Accepted on 2026-11-24. The owner selected option B in the PWFA architecture discussion. The historical record supplies the sample counts. The grid shapes are a new choice for the first numerical torus baseline. [Recovered sweep](ADR-076b.md) · [Numerical contract](../mathematics/numerical-methods.md)

## Decision

Use a uniform periodic grid on the unit square torus. Record the number of sites along each axis as $N_x$ and $N_y$. The sample budget is $N=N_x N_y$.

| Total sites | $N_x$ | $N_y$ | Spacing along $x$ | Spacing along $y$ |
|---:|---:|---:|---:|---:|
| 128 | 16 | 8 | 1/16 | 1/8 |
| 256 | 16 | 16 | 1/16 | 1/16 |
| 512 | 32 | 16 | 1/32 | 1/16 |

## Alternatives discussed

- **A. Separate solver resolution from the benchmark sample budget.** The assistant recommended square validation grids of 32×32, 64×64, and 128×128. These refine both axes together and require a separate mapping to the benchmark samples.
- **B. Preserve the total site budget.** The owner selected 16×8, 16×16, and 32×16. These preserve the historical sample counts and use equal spacing along both axes at the middle level.
- **C. Interpret the counts per axis.** Square grids of side 128, 256, and 512 would preserve axis symmetry and substantially increase the cost of a dense pairwise memory.

## Consequences for validation

The first refinement halves the spacing along $y$. The second halves it along $x$. A change between adjacent levels therefore measures refinement along one direction. Axis-aligned waves have equal continuum rates, while a rectangular grid can give them different numerical rates. Future validation should report each axis error against the corresponding exact rate and identify both grid dimensions.
